## [0.4.0] — 2026-11-20

**Первый публичный выпуск семейства v0.4.x:** [GitHub Release v0.4.0](https://github.com/uzbatsu-beep/IP_PORT/releases/tag/v0.4.0), Windows x64, Linux x64, macOS ARM64/x64 и `SHA256SUMS.txt`. Код опубликован по проверенному тегу `v0.4.0`; перечисленные ниже изменения вошли в этот релиз.


### PR #9 — неблокирующая и сохраняемая база IEEE OUI
- Импорт и проверка официальных IEEE CSV вынесены из потока `egui` в фоновый поток с индикацией состояния.
- После успешной проверки файл копируется в локальный каталог данных IP_PORT; MA-L/MA-M/MA-S автоматически восстанавливаются при следующем запуске без сетевых загрузок.
- Каждая замена кэша выполняется через временный файл и резервную копию предыдущей версии с восстановлением после прерванной операции.
- Неверный CSV не изменяет ни текущую базу, ни ранее сохранённый реестр; ошибку можно увидеть в интерфейсе.
- `Reset OUI` удаляет сохранённые пользовательские реестры, возвращая компактную встроенную базу производителей.
- Добавлены тесты многофайлового восстановления, отказоустойчивой замены и восстановления после прерывания.


### PR #7 — IEEE OUI, интерфейсы и контроль времени PTR (v0.4.x)
- Подключаемые офлайн CSV-реестры IEEE MA-L (24 бита), MA-M (28 бит), MA-S (36 бит) с приоритетом максимально специфичного префикса; импорт каждого класса атомарен и ограничен 16 МиБ.
- Загрузка справочников в разделе Host identification с отображением количества записей и сбросом. Встроенные соответствия остаются резервным вариантом.
- Кэш ARP/NDP теперь учитывает сетевой интерфейс; для неоднозначного IP на нескольких адаптерах MAC не присваивается произвольно, а в подсказке видны кандидаты.
- Конфигурируемый порог предупреждения PTR (500–30 000 мс) в профиле сканирования; показываются активные и суммарные превышения.
- Это мягкий срок диагностики: заблокированный вызов системного DNS-резолвера не прерывается принудительно; текущий пул остаётся ограниченным двумя потоками.


### PR #6 — Windows MAC/OUI и диагностика PTR (v0.4.x)
- Для Windows чтение кэша соседей переведено с текстового `arp -a` на `GetIpNetTable2` (IP Helper API), доступны IPv4/ARP и IPv6/NDP без активного сетевого опроса или зависимости от локализации команд.
- Для каждого IP сохраняются состояние PTR (`Resolved`, `No PTR name`, `Resolver error`, `Disabled`), продолжительность запроса и диагностическое сообщение об ошибке.
- Интерфейс показывает счётчики PTR-результатов, ошибок получения кэша соседей, найденных MAC, выполненных запросов и длину ожидающей очереди.
- Введён повтор отправки запросов в ограниченную очередь (512): при кратковременной перегрузке уникальные хосты больше не теряются без уведомления.
- Добавлены тесты классификации PTR и обработки серии из 850 уникальных IP без сетевых запросов.
- Ограничения: системный PTR resolver может блокировать выделенный рабочий поток; MAC удалённых хостов и полное IEEE OUI-определение не гарантируются; link-local IPv6 на разных интерфейсах может иметь одинаковый IP.


### Стабилизация базы сервисов (PR #5)
- Удалена утечка памяти `Box::leak`: база сервисов владеет именами портов, а каждый результат сканирования хранит независимую копию имени сервиса.
- Загрузка внешнего справочника выполняется без удержания глобальной блокировки чтения/записи; после успешного разбора вся база атомарно заменяется.
- При ошибке импорта прежний справочник остаётся без изменений. Повторная загрузка заменяет предыдущие внешние переопределения, сохраняя встроенные сервисы.
- Входной файл базы сервисов ограничен 16 МиБ; сообщение об успешном `Reset` отображается в интерфейсе.
- Добавлены тесты повторных импортов, атомарности отказа и сохранения имён сервисов в уже собранных результатах.


### Исправлено — Windows: раскрытие Services database
- Устранено создание временного массива ~1 МиБ в стеке потока при инициализации справочника сервисов (`Box::new([None; 65536])`).
- Таблица для 65 536 портов теперь создаётся непосредственно в куче (`vec![None; 65_536].into_boxed_slice()`), сохраняя O(1) доступ по номеру порта.
- Добавлен регрессионный тест создания встроенной базы на потоке со стеком 256 КиБ, близком к ограниченным стекам UI.
- Исправление устраняет подтверждённый риск stack overflow; сообщение `msedgewebview2.exe` требует отдельной проверки журнала Windows, так как процесс не является нативным рендерером egui.


### Исключения целей, PTR и MAC/OUI (PR #3)
- Exclude Targets: IPv4/IPv6 адреса, CIDR и диапазоны без расширения сетей; применяется после A/AAAA DNS-резолвинга, так что исключённые адреса не получают TCP/UDP-проб.
- Предпросмотр количества исключённых IP, проверка некорректных правил до запуска; сохранение настроек в совместимых JSON-профилях.
- Опциональное фоновое PTR-разрешение найденных уникальных IP и чтение системного ARP/NDP-кэша (без отправки дополнительных активных проб).
- Локальное определение OUI и ряда известных производителей; неизвестный производитель не угадывается, MAC удалённых узлов обычно недоступен.
- PTR/MAC/OUI отображаются в таблице и группировке хостов, доступны для поиска, добавляются к JSON и HTML экспорту. Формат CSV v1 сохраняется без изменений.
- Регрессионные тесты для исключений, системных соседей, IEEE OUI и безопасного HTML/JSON экспорта.



## [0.3.1] — 2026-11-19

### Исправлено
- Восстановлена сборка macOS Intel в релизном workflow: `macos-13` заменён на поддерживаемый `macos-15-intel`; публикация релиза выполняется только по тегу после успешных сборок всех платформ.
- Исправлена статистика времени отклика UDP: состояния `Open|Filtered` не содержат подтверждённого RTT и исключены из гистограммы и агрегатов.
- Таблица результатов отображает отсутствие RTT для `Open|Filtered` символом `—`. Экспорт: CSV — пустое поле `rtt_ms`, JSON — `null`, HTML — `N/A`; без ошибочного приравнивания таймаута к задержке.
- Устранена квадратичная сложность группировки результатов по IP благодаря индексации хостов через `HashMap`.
- Статистика RTT кэшируется до изменения набора результатов вместо пересортировки при каждом кадре интерфейса; сводка хоста показывает N/A, когда подтверждённых ответов нет.
- Отмена сканирования прерывает выполняющийся асинхронный DNS-запрос немедленно через `tokio::select!`.
- Добавлены регрессионные тесты для UDP RTT, семантики экспорта, группировки хостов и кэша статистики.

### Совместимость
- В JSON/CSV схеме v1 при `Open|Filtered` поле `rtt_ms` теперь обозначает отсутствие измерения; для подтверждённых `Open` числовой формат не изменён. Потребителям данных следует учитывать `null` и пустое CSV-поле.

## [0.1.0] — 2026-11-17

### Добавлено

#### Сетевой движок (TCP & UDP)
- **Асинхронный масштабируемый движок на Tokio:**
  - Генерация заданий по требованию (on-demand) без аллокации всех комбинаций адрес/порт в памяти.
  - Настраиваемая параллельность (1–1024 воркеров) и таймауты подключения (50–5000 мс).
  - Поддержка немедленной отмены через `CancellationToken` без зависания активных соединений.
- **Поддержка сетевых протоколов:**
  - Сканирование TCP Connect с измерением точного RTT подключения.
  - Сканирование UDP со специализированными RFC-пробами для популярных служб:
    - DNS (порт 53): валидный A-query (RFC 1035).
    - NTP (порт 123): клиентский запрос NTPv4 (RFC 5905).
    - SNMP (порт 161): SNMPv1 GetRequest (RFC 1157).
    - NetBIOS (порт 137): Node Status Request (RFC 1002).
    - Универсальный однобайтовый fallback `b"\0"`.
  - Трёхпозиционная модель классификации результатов UDP:
    - `Open`: получен явный датаграмм-ответ.
    - `Open|Filtered`: таймаут без ответа и без ICMP (неоднозначный исход по RFC 768 / RFC 1812).
    - `Closed` (`Refused`): асинхронный перехват ICMP Port Unreachable через подключенный UDP-сокет (`WSAECONNRESET` на Windows, `ECONNREFUSED` на Linux/macOS).
  - Адаптивный контроль параллельности для UDP ($\le 64$) из-за ограничения частоты ICMP ядрами ОС.
- **Адресация и цели:**
  - Одиночные IPv4 и IPv6 (`127.0.0.1`, `::1`).
  - CIDR-подсети (IPv4 до `/16`, IPv6 до `/120`, до 256 хостов).
  - Диапазоны адресов IPv4 (`start-end`) и IPv6 (`start_v6-end_v6` до 65 536 адресов).
  - Явная диагностика несовместимости с zone identifiers IPv6 (`%zone`).
  - Поддержка DNS-имён хостов (FQDN, `localhost`, `router.local`, `scanme.nmap.org`):
    - Синтаксическая валидация по RFC 1123 / RFC 952 в UI без сетевых обращений.
    - Асинхронное Dual-Stack разрешение A и AAAA записей перед стартом воркеров.
    - Дедупликация и защита от превышения лимита 65 536 адресов на запуск.
- **Определение сервисов и захват баннеров (Banner Grabbing):**
  - База соответствия портов `ServicesDb` со сложностью O(1) и поддержкой форматов `nmap-services`, `/etc/services` и IANA CSV.
  - Опциональный захват приветственных баннеров (SSH, FTP, SMTP, VNC, POP3, IMAP) и probe-баннеров (HTTP HEAD) с отдельным таймаутом (100–5000 мс), строгим ограничением буфера (256 байт) и визуальной отметкой подтверждения (`✔`).

#### Графический интерфейс (GUI)
- Современный тёмный интерфейс на `eframe` / `egui` с нативным ускорением через `glow`.
- Таблица результатов без визуального шума вертикальных разделителей колонок.
- Полная клавиатурная навигация: стрелки Up/Down, Home, End, Enter/Space (открытие веб-портов или копирование), Ctrl/Cmd+Enter (старт), Escape (стоп), Ctrl/Cmd+F (фокус фильтра), Ctrl/Cmd+C (копирование).
- Контекстное меню по правому клику с автоматическим выделением строки.
- Всплывающие toast-уведомления с таймером и анимацией fade-out.
- Сводные агрегированные счётчики закрытых портов, таймаутов, `Open|Filtered` и сетевых ошибок без расхода памяти на каждую неудачную пробу.
- Лимит хранения открытых результатов — 100 000 строк.

#### Данные, экспорт и профили
- Сохранение и загрузка версионируемых JSON-профилей настроек (схема v1) с атомарным откатом при ошибках валидации.
- Асинхронный экспорт снимка данных в CSV и JSON (схема v1) в отдельном системном потоке с потоковым экранированием по RFC 4180 и RFC 8259.
- Кликабельный путь сохранения экспорта с генерацией timestamp-имён по умолчанию (`scan_results_YYYYMMDD_HHMMSS.{ext}`).

#### Инфраструктура и качество
- 71 автоматический модульный и интеграционный тест, покрывающий сетевые операции, отмену, ошибки, GUI-состояние и нагрузочные сценарии (136 FPS на 20 000 результатов).
- Автоматический CI/CD пайплайн в GitHub Actions для Windows, Linux и macOS с проверками форматирования (`cargo fmt --check`), линтинга (`cargo clippy --all-targets -- -D warnings`), тестов и MSRV (Rust 1.95.0).
- Автоматизированная матричная сборка релизных пакетов и публикация на GitHub Releases с контрольными суммами SHA256.
