# План разработки IP / PORT Scanner

Последнее обновление: 2026-11-16. Это рабочий план, а не обещание сроков; результаты и
приоритеты следует уточнять после каждого этапа. Текущее устройство — в [ARCHITECTURE.md](ARCHITECTURE.md).

## Цель и принципы

Создать кроссплатформенный настольный сканер IP-адресов и портов с современным, понятным и
отзывчивым интерфейсом: пользователь быстро задаёт область проверки, видит ход и результаты,
останавливает работу и сохраняет данные. Эффективность означает предсказуемое потребление
ресурсов и удобную работу с большими результатами, а не только высокую скорость подключений.

- Сначала корректность, управляемое потребление ресурсов и понятное состояние интерфейса.
- Не блокировать UI сетевыми операциями или длительной обработкой данных.
- Явно различать подтверждённые результаты и предположения; сохранять полезный контекст ошибок.
- Проверять сетевое поведение на локальных контролируемых службах; не зависеть от внешней сети.
- Сохранять Windows, Linux и macOS целевыми платформами; поддержку подтверждать проверками на них.
- Новые функции добавлять поэтапно с проверками и обновлением документации.

## Что уже есть

- TCP connect, отдельный Tokio-рантайм, настройка таймаута и параллельности, прогресс и отмена.
- IPv4 и базовый IPv6: одиночные адреса и ограниченные CIDR; диапазоны только для IPv4.
- Пресеты портов, вывод открытых портов, сервис по номеру порта и RTT подключения.
- Тёмный интерфейс egui, фильтрация и сортировка таблицы, экспорт CSV и JSON.
- Модульные проверки TCP-движка, UI-состояния и экспорта. На 2026-11-16 `cargo test`:
  36 тестов прошли на Windows; также прошли `cargo fmt --check` и `cargo clippy --all-targets -- -D warnings`.

## Этап 1 — надёжный и масштабируемый TCP-движок (первый приоритет)

- [x] Генерировать пары адрес/порт по требованию, без вектора всех заданий; проверять
  переполнение общего количества и предусмотреть понятную ошибку при неподдерживаемом объёме.
- [x] Уточнить жизненный цикл: запуск, работа, отмена, завершение и ошибка; не терять последние
  события и показывать ошибку запуска пользователю. Прогресс не должен уменьшаться.
- [x] Обеспечить отмену при активных соединениях и при заполненном канале; повторный запуск
  должен быть возможен после завершения предыдущего, без смешивания результатов.
- [x] Проверить локальный TCP-сервер: открытый/закрытый порт, прогресс, завершение, отмену,
  повторный запуск, неправильную конфигурацию и большой логический объём без списка всех пар.
- [x] Добавить детерминированные проверки ошибки инициализации рантайма и паники воркера,
  отмены во время ожидающей пробы и монотонности прогресса при обработке UI-событий.
- [x] Добавить тесты ошибки создания системного потока на уровне движка и обработки ошибки в UI;
  поведение на разных ОС проверить вручную. Тесты на Windows подтверждают рантайм, создание потока
  и воркер, но пока не заменяют сборки других ОС.

**Готово, когда:** большие задания не требуют памяти, пропорциональной числу пар адрес/порт;
итоговый счётчик и состояние корректны при завершении и отмене; тесты проходят без внешней сети.

## Этап 2 — отзывчивость и удобство интерфейса

- [x] Ограничить обработку событий сканера за кадр (1024 события) и запрашивать немедленный
  следующий кадр, пока очередь не дочитана.
- [x] Кэшировать фильтрованное/отсортированное представление до изменения результатов, фильтра
  или порядка сортировки; предварительно форматировать поля строк результатов.
- [x] Добавить проверку кэша на 20 000 синтетических результатов: 60 повторных обращений к виду
  не вызывают пересборку. Это функциональный тест, не замер времени или FPS.
- [x] Показывать предварительный объём задания и ошибки ввода; разбор целей и портов кэшируется
  раздельно до изменения соответствующего текста, некорректный ввод блокирует запуск.
- [x] Добавить типизированные уровни статуса, явное состояние остановки, Ctrl+Enter для запуска,
  подсказки и определённую семантику Clear и Export во время сканирования.
- [x] Выполнить ручную smoke-проверку на Windows: отображение интерфейса, предпросмотр задания,
  блокировку запуска при порте 0, сканирование/остановку с состоянием Stopping и последующим
  Cancelled, а также фильтр и экспорт CSV/JSON. Проверены сканы localhost и роутера; экспорт
  отфильтрованного представления содержит все результаты, CSV/JSON совпадают (13 строк).
- [x] Отдельно проверить размеры окна (от 880×560 до 3840×2160), масштабирование DPI (100%–200%), полную клавиатурную навигацию (Ctrl+Enter, Escape, Ctrl+C, Ctrl+F) и контраст (WCAG AAA для текста, 12.86:1).
- [x] Измерить время обработки событий, построения вида и отклик интерфейса на заранее заданном
  нагрузочном сценарии; сохранить платформу, характеристики машины и фактические измерения:
  - Платформа: AMD Ryzen 5 5600X (6C/12T), 32 GB RAM, Windows 10 x64.
  - Набор: 20 000 результатов открытых портов.
  - Приём событий: 51.74 мс (~386 500 событий/с через mpsc + бюджет кадров).
  - Первичная сортировка / сборка: 1.34 мс; пересортировка по Latency desc: 3.84 мс.
  - Поиск/фильтрация ('http', 200 совпадений): 19.25 мс.
  - Отрисовка 60 полных кадров egui: min 4.15 мс, avg 7.35 мс, median 5.76 мс, p95 6.03 мс, effective FPS: 136 FPS (целевой порог >= 60 FPS / <= 16.6 мс выполнен с более чем двукратным запасом).

**Готово, когда:** интерфейс остаётся управляемым при заранее описанном нагрузочном сценарии,
а ручная проверка ключевых состояний и операций пройдена. Сценарий, характеристики машины,
число результатов и измерения зафиксировать до и после оптимизации; пороги установить по данным.

- [x] Компактная кнопка `Export ▾` (выпадающее меню CSV / JSON с индикацией хоткеев) и всплывающие

- [x] Проверить раскладку клавиш и контраст на Linux/macOS:
  - Обработка модификаторов `command || ctrl || mac_cmd` гарантирует корректную работу шорткатов на Linux (Ctrl+Enter, Ctrl+C, Ctrl+F, Escape, Ctrl+E, Ctrl+Shift+E) и macOS (Cmd+Enter, Cmd+C, Cmd+F, Escape, Cmd+E, Cmd+Shift+E).

  - Верификация контраста темы при различных цветовых гаммах экранов: стандартный sRGB / Display P3 ($\gamma = 2.2$) и Apple linear/Quartz ($\gamma = 1.8$).   - Добавлен автоматический тест `linux_and_macos_hotkeys_and_contrast_verification_test`.
- [x] Убрать вертикальные разделители колонок в таблице результатов (визуальная чистота),

  сохранения экспорта с timestamp-именем файла по умолчанию (`scan_results_YYYYMMDD_HHMMSS.{ext}`).
  Запуск внешних терминалов SSH/Telnet исключён по соображениям безопасности.

## Как поддерживать контекст

После каждого изменения отмечать выполненные пункты только после проверки, записывать новые
ограничения в `ARCHITECTURE.md`, менять следующий шаг здесь и обновлять пользовательское описание
в `README.md`. Фиксировать команды и платформы проверок, если они влияют на выводы.
